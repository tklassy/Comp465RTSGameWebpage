Development Changelog

A chronological record of features, fixes, and changes made during development of the COMP 465 RTS project. Individual changes can be expanded to view their implementation documentation.

October 20, 2026 Health, Factions, Destruction, and Enemy Base Updates
Added World-Space Health Bars

Vehicles and buildings now use reusable world-space health bars connected to SelectableHealth.

Health bars remain hidden while an object is at full health and automatically appear after the object takes damage. The remaining health is displayed in green while missing health is displayed in red.

The bars use a World Space Canvas and remain horizontally aligned with the camera so they are readable throughout the battlefield.

Updated Selected Object Health Display

The SelectedInfoPanel health display was updated to use the same red and green health representation as the world-space health bars.

The green health image now changes width using RectTransform anchors instead of Unity's Filled Image mode. This allows the cleaner UISprite using the Simple image type to be retained.

Updated Production Progress Bar

The production progress bar now uses the same anchor-based resizing approach as the health interface.

This allows the production fill to use a Simple UISprite instead of changing back to Unity's Filled image type during runtime.

Moved Faction Ownership to SelectableUnit

Faction ownership was moved out of CombatUnit and into SelectableUnit.

Every selectable object can now be assigned to the Player, Enemy, or Neutral faction regardless of whether that object has combat capabilities.

This separates ownership from combat behavior. CombatUnit now represents whether an object can fight, while SelectableUnit determines who owns the object.

Added Enemy and Neutral Selection Rules

Enemy and Neutral objects can now be selected and inspected by the player without becoming controllable.

CommandPanelManager prevents non-player objects from exposing player commands, while UnitCommandManager filters movement, logistics, and route commands so only Player-owned vehicles respond.

Resource nodes can therefore remain Neutral, enemy vehicles can be inspected, and enemy buildings can use the same selection system as player structures.

Expanded Combat Targeting to Buildings

Combat targeting no longer requires the target to also have a CombatUnit component.

A valid target now uses SelectableHealth and SelectableUnit. CombatUnit checks the faction stored on SelectableUnit to determine whether the object is hostile.

This allows enemy vehicles to attack Player-owned buildings without giving every building a weapon or CombatUnit component.

Added Manpower Release When Units Are Destroyed

Produced units now receive manpower tracking when production completes.

When one of those units is destroyed, its manpower cost is removed from manpowerUsed. This returns the consumed manpower capacity to the player.

Enemy-spawned units do not use the Player manpower system because they are not registered through the Player production queue.

Updated Barracks Destruction and Manpower Capacity

Barracks now remove their manpower-cap increase when they are destroyed.

ResourceManager was also updated so the manpower cap can fall below currently used manpower. Existing units remain alive, but additional production is blocked until manpower usage falls back below the available capacity.

For example, destroying a Barracks while using 22 manpower can immediately change the display from 22 / 22 to 22 / 12.

Verified Resource Cleanup on Destruction

Destruction behavior was tested for both cargo vehicles and resource warehouses.

Resources carried by a destroyed vehicle are automatically removed from the top bar's In Transit total because the VehicleCargo object no longer exists.

Resources stored inside a destroyed warehouse are likewise removed from the Stored resource totals.

Converted Enemy Spawner Into a Destructible Building

EnemySpawner was moved onto the enemy production building itself instead of existing as a separate object that creates a building.

The building continuously produces enemy vehicles and assigns them to the configured EnemyAttackRoute.

When the building reaches zero health, spawning stops. If Destroy On Death is enabled, destroying the building also destroys the EnemySpawner component with it. Enemy vehicles that were already created continue following their assigned attack route.

Updated Weapon Tracer Material

The combat tracer was updated to use a compatible Universal Render Pipeline material.

The corrected material prevents the LineRenderer from appearing magenta when its shader is unsupported. The current weapon tracer is displayed in yellow.

October 19, 2026 Combat and Enemy AI
Added Headquarters Quick Access

A quick-access button was added to the bottom HUD to provide faster access to the player's Headquarters.

The first click searches UnitSelectionManager for a selectable Headquarters and makes it the active selection. If the Headquarters is already the only selected object, clicking the button again centers the RTS camera on it.

RTSCameraController was updated with reusable focus methods so both UI buttons and the existing Space-key behavior can use the same camera-centering system.

Added Enemy Attack Routes

A predefined enemy attack-route system was added to provide reliable long-distance enemy movement.

EnemyAttackRoute reads child waypoint objects in Hierarchy order. EnemyRouteFollower then moves a NavMeshAgent from one waypoint to the next until the route is complete.

This allows the overall strategic path to be manually defined while still allowing NavMesh to handle smaller navigation decisions between route points.

Added Enemy Vehicle Spawning

EnemySpawner was introduced to continuously generate enemy vehicle forces at a configurable interval.

When a vehicle is instantiated, the spawner finds its EnemyRouteFollower and assigns the configured EnemyAttackRoute.

Added the CombatUnit System

CombatUnit was created as a reusable combat component for armed units.

It handles hostile target detection, weapon timing, damage, targeting range, optional turret rotation, and weapon tracer display.

Units periodically search nearby colliders and select the closest valid hostile target within range.

Connected Combat to SelectableHealth

Combat uses the existing SelectableHealth component rather than maintaining a separate combat health system.

Weapon attacks call TakeDamage on the target. Objects with Destroy On Death enabled are destroyed when their health reaches zero.

Added Weapon Tracers

A LineRenderer tracer was added to make automatic weapon fire easier to identify.

Damage is applied immediately to the selected target while the LineRenderer briefly displays the path between the weapon's FirePoint and the target.

Tracer width and duration are Inspector-adjustable so future weapons can use different visual characteristics.

October 14, 2026 Command and Production Refactor
Refactored the Command System

CommandPanelManager was reorganized so the central manager only handles the shared 3×4 command grid and keyboard input.

Individual selectable objects provide their own available commands through components such as HumveeCommands, HDTCommands, FuelTruckCommands, and production-building command scripts.

Shared behavior is provided through VehicleCommandsBase and ProductionBuildingCommandsBase.

Added Reusable Vehicle Construction

VehicleConstruction was converted into a generic reusable construction component.

Individual vehicle command scripts now contain references to the structures that vehicle is permitted to construct. This prevents the central command system from containing references to every building in the game.

Added BuildingProductionQueue

BuildingProductionQueue was created as a reusable production system for Headquarters and other production buildings.

Each production option can define its prefab, production time, manpower requirement, and physical resource costs. Resources and manpower are reserved or spent when production is queued.

Completed units spawn at the configured production point and can automatically move toward the building's rally point.

Expanded Selected Object Information

The bottom information panel was expanded to display reusable information for vehicles, buildings, resources, health, cargo, and production.

Production buildings display the item currently being built, percentage completion, progress, and queued production count.

Added Reusable Selection Data and Health

SelectableInfoData and SelectableHealth were added as reusable components for selectable game objects.

These systems provide common display information and health behavior without requiring each unit or building type to implement its own version.

October 8, 2026 Construction and Logistics
Added Grid-Based Construction

A 10×10 world grid was added for structure placement. GridManager converts world positions into grid coordinates, snaps structures to cell centers, and tracks occupied and reserved cells.

Building placement uses a ghost preview before construction. Valid and invalid positions use different preview materials.

Added Vehicle Construction Orders

Buildings are constructed using Player vehicles instead of appearing immediately after placement.

A vehicle receives a construction order and moves toward the selected build location. Shift-based placement allows additional construction orders to be queued.

Added NavMeshObstacle Building Carving

Completed buildings use NavMeshObstacle carving so vehicles navigate around finished structures.

Placement ghosts keep their obstacles disabled so temporary previews do not block navigation.

Added Specialized Resource Warehouses

Physical resource storage was moved into specialized warehouse buildings.

Wood, Metal, Electronics, Fuel, Water, and Food can each be stored in warehouses configured for that resource type. Warehouse capacity and starting amounts are configurable.

Added Vehicle Cargo

VehicleCargo allows logistics vehicles to physically transport resources between resource nodes and warehouses.

Vehicles can be configured to carry all resources or only selected resource types, with cargo capacity adjustable by vehicle.

Added Warehouse Transfer Points

Warehouse Shipping and Receiving points provide destinations for logistics vehicles to transfer physical resources.

Cargo compatibility and warehouse resource types determine which resources can be transferred.

Added Persistent Logistics Routes

Persistent vehicle routes were added for repeated logistics operations.

Routes can contain road waypoints, resource nodes, and warehouse transfer points. Route markers remain associated with the vehicle and can be shown when it is selected.

Added Physical Resource Nodes

Resource nodes provide physical materials that logistics vehicles can collect.

Resource type, amount, capacity, refill behavior, and route stop position can be configured for each node.

Added Resource Top Bar and Hover Breakdown

The top HUD displays Money and the total amount of each physical resource currently owned.

Physical totals include resources stored in warehouses and resources currently being transported by vehicles.

Hover information provides a breakdown of the warehouses and vehicles currently holding each resource.

Added Manpower Capacity

A manpower system was added to limit the number of units the Player can field.

Production options can require manpower, and structures such as the Barracks increase the available manpower cap.

September 21, 2026 Initial RTS Systems
Created the Initial RTS Project and Scene

The initial COMP 465 RTS Unity project and playable scene were created as the foundation for the game.

Added the RTS Camera

The RTS camera supports arrow-key movement, screen-edge scrolling, mouse-wheel zoom, and focusing on selected units.

Added NavMesh Vehicle Movement

Unity's NavMesh system was added to provide basic vehicle pathfinding across the RTS map.

The first controllable vehicle used a NavMeshAgent to move to Player-issued destinations.

Added RTS Unit Selection

UnitSelectionManager and UnitSelectionBox were created to support both individual click selection and traditional RTS drag-box selection.

Selectable objects use visual selection indicators that appear when selected and disappear when deselected.

Added the Headquarters

The Headquarters was introduced as the first selectable Player building.

Early production functionality allowed the Headquarters to create vehicles and send newly produced units toward a rally point.

Added the 3×4 Command Panel

A Warcraft-style 3×4 command grid was created using the QWER, ASDF, and ZXCV keyboard layout.

This interface became the foundation for the later dynamic command system used by vehicles and buildings.
