Project Overview

An overview of the design and major systems of the COMP 465 real-time strategy game.

As of: November 3, 2026

Game Concept

The project is a modern military real-time strategy game developed in Unity. The game combines traditional RTS base building and unit control with a larger emphasis on logistics, transportation, resource movement, and supporting military operations.

Vehicle Control

Vehicles are the primary controllable units. The Player can select individual vehicles or groups, issue movement commands, establish logistics routes, and construct buildings.

Selectable objects use Player, Enemy, and Neutral factions. Enemy and Neutral objects can be selected and inspected, while Player command systems only allow Player-owned units to receive orders.

Base Building

Buildings are placed on a 10×10 world grid using vehicle-based construction. Current structures include the Headquarters, Barracks, Heavy Truck Production Depot, Tracked Vehicle Production, maintenance facilities, and specialized resource warehouses.

Building prefabs use configurable construction costs. Placement checks affordability before accepting an order, and canceled unfinished construction orders refund their paid resources.

Buildings can have health, selection information, faction ownership, and NavMesh obstacles without requiring combat capabilities.

Resources and Logistics

The economy currently includes Money, Food, Water, Fuel, Wood, Metal, and Electronics. Physical resources are stored in specialized warehouses and transported by cargo vehicles.

The resource interface tracks both warehouse storage and resources currently in transit. Destroyed cargo vehicles and warehouses automatically remove their contents from the displayed totals.

The long-term goal is for logistics to directly support construction, production, and combat operations.

Production and Manpower

Production buildings use reusable production queues. Individual units can require resources, manpower capacity, and construction time before they are spawned.

Produced units consume manpower while they exist and release that manpower when destroyed. Barracks increase the manpower cap and remove that additional capacity if the Barracks is destroyed.

The game supports temporary over-cap states. Existing units remain active if a Barracks is lost, but additional units cannot be produced until manpower usage falls back below the available cap.

Combat

Armed vehicles can automatically detect hostile Player or Enemy objects, rotate toward targets, fire weapons, deal damage, and destroy targets. Direct-fire weapons use HitscanAttack and can require turret alignment before firing.

LongRangeProjectileAttack provides reusable indirect-fire behavior with launcher rotation, minimum range, arcing projectiles, salvo timing, configurable spread, splash damage, and impact effects. Current combat vehicles include the Battle Tank, HIMARS, and Tracked Artillery.

Faction ownership remains independent from weapon behavior, allowing non-combat buildings to be valid combat targets without giving those buildings weapons.

Damaged units and buildings display world-space health bars with remaining health shown in green and missing health shown in red. Direct-fire weapons use visible yellow LineRenderer tracers while long-range projectiles use visible impact effects.

Enemy Forces

Enemy vehicles use predefined waypoint routes and NavMesh navigation to travel toward the Player's base.

Enemy production is currently handled by a destructible enemy building. The building periodically spawns enemy vehicles and assigns them to the configured attack route. Destroying the production building stops future enemy vehicle spawns.

User Interface

The HUD provides resource totals, manpower, game time, selection information, health, cargo information, production progress, and command controls.

An in-game menu provides Return to Game, Controls, Settings, Dev Commands, and Exit Game options. The developer panel can remain open independently and includes resource controls for testing.

Command-button hover tooltips are being integrated using shared prefab and production data for names, descriptions, resource costs, and manpower requirements.

Health and production bars use reusable Simple UISprite-based displays that resize using anchors rather than Unity Filled Image rendering.

Tablet-Based Command Interface

The planned interface direction is built around a military-style tablet system that gives the Player a consistent way to access logistics, economy, production, objectives, alerts, upgrades, and other detailed information.

During normal gameplay, most of the primary tablet will remain hidden above the screen. Only its lower edge will remain visible, forming the existing top HUD and displaying important information such as Money, Manpower, resources, game time, and alerts.

When the Player selects information that requires a larger interface, the tablet will slide down and occupy a larger portion of the screen. The tablet itself will become the background and frame for the selected management page instead of opening an unrelated full-screen menu.

Different pages can provide access to logistics networks, resource storage, production, Player economy, objectives, supply warnings, strategic overlays, and future upgrades. Selecting information from the normal HUD should open the tablet directly to the relevant page.

The battlefield will remain the primary gameplay space. Movement, combat, construction, selection, and the command panel will remain immediately accessible without requiring the main tablet to be opened.

Smaller HUD elements will follow the same physical-interface concept. The command panel, selected-object information panel, and other UI elements can appear as smaller tablet displays or military electronic devices, giving the interface a consistent visual identity without making every panel part of the main tablet.

These smaller displays can also include decorative buttons, indicators, and occasional hidden interactions or Easter eggs that do not interfere with normal gameplay.

Tablet pages can also control information displayed directly over the battlefield. A logistics or supply page could enable overlays for active routes, resource nodes, warehouses, vehicle cargo, weapon ranges, low-supply warnings, and production shortages while the Player continues viewing the game world.

Planned Features

  • Player Attack and Attack-Move commands
  • Fog of war with Hidden, Explored, and Visible states
  • Additional muzzle flashes, explosions, and destruction effects
  • RTS-style enemy base AI using the same economy, construction, production, and logistics rules as the Player
  • Construction sites requiring delivered resources
  • Import and export logistics systems
  • Minimap
  • Building and unit upgrades
  • Aircraft and helicopters
  • Improved road-based vehicle navigation
